Cryptiki legacy migration

Temporary, client-side recovery for Cryptiki v1/v2. The old password and recovered text stay in this browser; clearing is best effort because browser memory cannot be reliably wiped.

Recovery window closes 2027-01-26

Previous Cryptiki versions had several security issues:

  • v1 stored the password hash in a format (SHA-256) that modern hardware cracks fast.
  • v2 kept the password hash in the server database — and that hash was also the key to the user's vault data. The hash itself was never exposed to outside users directly.
  • Both had an SQL injection flaw which, combined with the above, risked extraction of most v1 data (except very long passwords) and all v2 data.

Capsules harden the new capsule store against a new capsule-only database disclosure. They cannot undo a previous disclosure of the legacy database's hashes or plaintext. Treat every recovered credential as potentially compromised and rotate important account passwords.

Use this tool to recover your data before the window closes. Afterwards create a fresh v3 vault with a new master password and rotate important passwords.

This tool never sends the page name or password. It sends only an opaque, memory-hard capsule lookup identifier.
